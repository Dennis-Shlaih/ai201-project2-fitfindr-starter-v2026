# Acceptance criteria — FitFindr

Five criteria that say what "working" means for this agent, written in unit 3
**before** any results existed.

An acceptance criterion names a target: a number, a count, a rate, or something
a person could plainly observe. *"The agent handles errors"* is an opinion.
*"When search returns nothing, the agent stops before calling the second tool,
in 5 of 5 tries"* is a criterion.

Under each one, write a sentence or two on **why that target** and not a
stricter one. A reason that says something about your tools, your loop, or the
data earns credit; *"80% seemed reasonable"* does not.

> Missing your own targets next unit costs you nothing. Setting a target so
> easy you can't miss it does.

**Two are written for you. You write three.**

---

## 1. A matching query completes all three tools

Given a query that matches at least one listing, the agent completes all three
tool calls and returns a fit card — in at least 4 of 5 tries.

**Why this target:**
I chose 4 of 5 because the search uses keyword matching, so some natural-language
phrasings may fail to find a listing even when the intent is similar. Requiring
most matching queries to complete the full pipeline still checks that the three
tools are connected correctly.

---

## 2. An impossible query stops before the second tool

Given a query that matches no listings, the agent stops before calling
`suggest_outfit` and returns a message naming what to change — 5 of 5 tries.

**Why this target:**
This branch is deterministic: an empty search result should always cause the
agent to stop before calling `suggest_outfit`. A 5 of 5 target checks that the
required branch is consistently enforced rather than depending on model output.

---

## 3. The selected item is preserved across tool calls

For 5 of 5 successful runs, the listing stored in `session["selected_item"]`
matches the listing passed to `suggest_outfit`, with the same `id`, `title`, and
`price`.

**Why this target:**
The selected listing is the state passed from the search step to the outfit
step. Comparing these fields in the session and tool-call trace makes that
transfer observable and catches cases where the agent passes a different item.


---

## 4. Fit cards meet the required format

For 5 different successful runs, every fit card is 2–4 sentences and mentions
the selected item's title, price, and platform.

**Why this target:**
The fit card is generated by a model, so its exact wording can vary. Checking
sentence length and the required item details tests whether each caption is
usable without requiring identical wording across runs.


---

## 5. The search respects the price ceiling

For 5 of 5 searches with a specified maximum price, every returned listing has
a price less than or equal to the requested maximum.

**Why this target:**
The price ceiling is a deterministic filter, not model-generated behavior. A
5 of 5 target checks that the search never returns an item above the user's
stated budget.
